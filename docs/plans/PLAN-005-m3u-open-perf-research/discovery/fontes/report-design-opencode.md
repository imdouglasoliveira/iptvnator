### Opção 1 — A-03: canais M3U em linhas no SQLite

**Encaixe / esquema proposto.** Tabela derivada de `playlists.payload`; o blob **continua sendo a fonte de verdade** e fallback.

```sql
CREATE TABLE IF NOT EXISTS m3u_channels (
  id           INTEGER PRIMARY KEY,
  playlist_id  TEXT NOT NULL REFERENCES playlists(id) ON DELETE CASCADE,
  position     INTEGER NOT NULL,            -- ordem original do M3U ("Playlist Order")
  group_title  TEXT NOT NULL DEFAULT '',
  url          TEXT NOT NULL,
  name         TEXT NOT NULL,
  tvg_id       TEXT, tvg_name TEXT, tvg_logo TEXT,
  radio        INTEGER NOT NULL DEFAULT 0,
  payload      TEXT NOT NULL               -- Channel completo: raw, http, catchup, drm, epgParams
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_m3u_ch_pl_pos  ON m3u_channels(playlist_id, position);
CREATE INDEX        IF NOT EXISTS idx_m3u_ch_grp_pos  ON m3u_channels(playlist_id, group_title, position);
CREATE INDEX        IF NOT EXISTS idx_m3u_ch_url      ON m3u_channels(playlist_id, url);
CREATE INDEX        IF NOT EXISTS idx_m3u_ch_grp_name ON m3u_channels(playlist_id, group_title, name, position);
CREATE VIRTUAL TABLE IF NOT EXISTS m3u_channels_fts USING fts5(
  name, content='m3u_channels', content_rowid='id', tokenize='trigram remove_diacritics 1'
);
```

Por que `payload` (JSON do `Channel`) e não colunas para tudo: `Channel` tem ~4 sub-objetos aninhados e `raw` (`libs/shared/interfaces/src/lib/channel.interface.ts:7-37`), e os 3 deltas do parser fork — `radio`, pipe stripping, `#KODIPROP` antes de `#EXTINF` — **devem sobreviver** (`docs/architecture/m3u-playlist-module.md:191-196`). Projetar só o que o SQL precisa e guardar o resto intacto evita uma migration por campo. `position` preserva o modo "Playlist Order" que hoje evita clonar a lista (`m3u:830-835`, `libs/ui/components/src/lib/channel-list-container/channel-list-sort.util.ts:44-51`).

**FTS5.** Trigram é o tokenizer que permite **substring** (`LIKE '%term%'`), equivalente ao `foldSearchText(...).includes(term)` atual (`all-channels-view.component.ts:145-149`); verificado em https://www.sqlite.org/fts5.html §4.3.4. Restrições a respeitar: substrings **< 3 caracteres não casam** (mesma exceção já tratada para Xtream em `docs/architecture/sqlite-db-worker.md:676-690`, `content-search.util.ts:9`) → manter fallback de prefixo; `remove_diacritics 1` exige SQLite ≥ 3.45 e é **probeado em runtime** no repo (`libs/shared/database/README.md:226-229`, `content-title-fts.ts:44-57`); tabela de conteúdo externo exige **triggers `ai/ad/au` + `rebuild`** para linhas pré-existentes (https://www.sqlite.org/fts5.html §4.4.3–4.4.4), modelo já implementado em `connection.ts:204-210` e `content-title-fts.ts:60-75`.

**Migração segura, repetível, que preserva dados (usuários pulam versões).**

### Opção 3 — Transporte em pedaços por `MessagePort`

**Encaixe.** Preload cria `MessageChannel`, envia uma ponta via `ipcRenderer.postMessage('port', null, [port1])` — padrão de **response streams** verificado em https://www.electronjs.org/docs/latest/tutorial/message-ports — e expõe a outra por `contextBridge` (`main.preload.ts:1370`), com o handoff isolated-world → main-world que o mesmo doc exige (`window.postMessage('main-world-port','*',event.ports)`). **Nuance concreta:** os dados vivem no `worker_threads` (`database.worker.ts`), e `MessagePortMain` (Electron) **não é transferível** para um `worker_threads.Worker`; o main precisa **relayar** os blocos entre `MessagePortMain` e `parentPort` (`database-worker-client.ts:128-133`).
